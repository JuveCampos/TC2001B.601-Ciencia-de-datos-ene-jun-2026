Metadatos — Cancelación de reservas de hotel

Dataset reservas_hotel.csv · 1500 observaciones · 19 variables · Curso de ML — CCM

Contexto del caso

Pregunta de negocio

Una cadena hotelera quiere anticipar qué reservas tienen alta probabilidad de ser canceladas antes del check-in, para gestionar mejor el inventario de habitaciones, ofrecer incentivos a clientes en riesgo y operar un programa de overbooking controlado.

Cada fila representa una reserva confirmada en el sistema de reservaciones del hotel. La variable objetivo registra si la reserva fue finalmente cancelada o si el huésped se presentó.

Variable objetivo

cancelo target

Variable binaria que indica si la reserva fue cancelada antes del check-in.

Clase positiva: "si" (la reserva se canceló). En el preprocesamiento se coloca como primer nivel del factor para que yardstick calcule sensibilidad, especificidad, precision y recall tomando "canceló" como evento de interés.

Distribución aproximada: 40 % si · 60 % no.

Relaciones esperadas (intuición de negocio)

Predictores asociados a mayor probabilidad de cancelar

  • Reservas hechas con mucha anticipación.
  • Canal OTA (Booking, Expedia, etc.) versus reserva directa.
  • Reservas con descuento alto o promoción.
  • Habitaciones de gama alta (suite, ejecutiva).
  • Temporada baja.

Predictores asociados a menor probabilidad de cancelar

  • Pago anticipado o depósito del 50 %.
  • Mayor número de solicitudes especiales (huésped comprometido con la estancia).
  • Cliente recurrente con historial de estancias previas.
  • Temporada alta.

Notas para el preprocesamiento

Receta recomendada

  1. step_impute_median() para precio_total_mxn y descuento_aplicado_pct.
  2. step_impute_mode() para pais_origen.
  3. step_nzv() — descarta predictores con varianza casi nula.
  4. step_corr(threshold = 0.85) — detecta colinealidad (atención: num_noches y num_noches_finde están correlacionados).
  5. step_normalize() — z-score sobre todas las numéricas.
  6. step_dummy() — codificación one-hot de las categóricas.

El identificador id_reserva debe excluirse con update_role(id_reserva, new_role = "id") antes de aplicar la receta.

En síntesis: el dataset está diseñado para practicar el ciclo completo de tidymodels con un problema de clasificación binaria realista, mezcla de variables numéricas y categóricas, faltantes intencionales y una clase positiva (canceló) lo suficientemente frecuente para que las métricas de sensibilidad y precisión sean interpretables sin necesidad de técnicas de remuestreo.
